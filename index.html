          How it works

          You type an address. This page asks one of the free public relays to fetch it. The relay sends the page back with permission headers that let a browser read it, and Relay then rewrites every link, image and stylesheet inside so they travel the same path. The result is shown in a sandboxed frame that cannot touch your settings or your recent list.

          The three modes

          • Full page — the real page, rewritten. Closest to normal browsing. Scripts are removed by default, so heavily interactive sites will look plain.
          • Reader — just the article text and its pictures. The most reliable mode, and the lightest on rate-limited relays.
          • Proxy instance — hands the whole job to a full web-proxy server you add yourself in settings. This is the only mode that can run a site's own scripts, because the server does the rewriting rather than this page.

          Adding your own relay

          Settings → Relays → Add a relay. The endpoint is the address of a service that fetches pages, with %URL% standing in for the target. Two shapes cover almost everything:

          • https://service.example/fetch?url=%URL% — keep percent-encoding on.
          • https://service.example/%URL% — turn percent-encoding off.

          Pick raw bytes if the service returns the page itself, json wrapped if it returns JSON with the page in a contents field, and text only if it returns readable text rather than HTML. If you run your own proxy server, add it as a proxy instance and use the proxy-instance mode.

          What this is not

          This is not a VPN. A VPN encrypts everything leaving your device and hides your address from the sites you visit. This moves one page request through a public relay, and that is all.

          Whoever runs a free relay can see which pages you ask for and everything in them. So: don't sign in to anything through it, don't send anything private, and treat every page you get back as something a stranger handed you. For accounts, banking or anything that matters, use the real connection.

          Why a page sometimes won't load

          • The relay hit its rate limit — wait a moment or pick another from the list.
          • The site blocks requests that don't come from a real browser. Reader mode gets through more often.
          • The page needs a login or a POST form. Free relays forward neither.
          • The site is built entirely in JavaScript, so there is no HTML to rewrite. Use a proxy instance.

          The failure screen lists every relay that was tried and what each one said, so you can tell a rate limit apart from a block.

          Where your data sits

          Settings, relays, measured speeds and the recent list are stored in this browser's local storage and nowhere else. Nothing here talks to a server of its own — there is no account and no backend. Clear your browser data, or hit Reset everything in settings, and it is all gone.
